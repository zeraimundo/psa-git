Atributos de arquivos • Debian 13

Proteção e seus limites

O atributo i bloqueia novas operações de escrita, remoção e renomeação. O atributo a restringe novas aberturas para escrita ao modo de acréscimo.

Um administrador ainda administra

Quem possui os privilégios necessários pode retirar i ou a. Eles ajudam contra alterações acidentais, mas não garantem proteção contra comprometimento administrativo.

E programas que já estavam com o arquivo aberto?

A documentação alerta que descritores já abertos não ficam protegidos retroativamente. Coordene a parada dos escritores antes de aplicar a política e teste o serviço depois.

Atributos de arquivos • Debian 13

Leitura com lsattr

lsattr politica-rede.txt
lsattr -l politica-rede.txt
lsattr -d backup
lsattr -R backup
lsattr -a .

A primeira forma mostra letras. -l usa nomes longos; -d consulta a pasta em si; -R percorre o conteúdo; -a inclui nomes ocultos.

O que significa e?

e indica uso de extents para mapear blocos do arquivo. É comum em ext4 e não representa uma proteção. A combinação e a posição das letras podem variar.

Atributos de arquivos • Debian 13

Imutabilidade com i

Leitura continua possível quando as permissões permitem. Escrita e remoção ficam bloqueadas enquanto i estiver ativo.

sudo chattr +i politica-rede.txt
lsattr politica-rede.txt
cat politica-rede.txt
Isso impede um link simbólico?

Não. Um link simbólico apenas guarda um caminho e pode apontar para o arquivo. A restrição envolve a criação de novos hard links para o inode protegido.

No laboratório, só tente apagar ou renomear depois de confirmar a letra i.

Atributos de arquivos • Debian 13

Acréscimo com a

sudo chattr +a conectividade.log
lsattr conectividade.log
echo "Novo teste autorizado" >> conectividade.log

As permissões de escrita continuam necessárias. a não concede acesso a quem não o tinha.

O registro fica impossível de falsificar?

Não. Quem pode acrescentar pode inserir informações falsas, e um administrador autorizado pode remover a restrição. Logs remotos, controle de acesso e monitoramento complementam a proteção.

Atributos de arquivos • Debian 13

Diretório protegido não congela tudo

i em uma pasta impede alterações nos nomes diretamente dentro dela, como criar e remover entradas. Isso não torna automaticamente imutável o conteúdo de cada arquivo existente.

sudo chattr +i backup
lsattr -d backup

Para incluir arquivos e subpastas já existentes, a atividade compara a operação simples com a recursiva.

sudo chattr -i backup
sudo chattr -R +i backup
lsattr -R backup

05. Testar o suporte aos atributos

O que fazer: Crie um arquivo de teste. Aplique i e consulte o resultado, nesta ordem.

O que fazer: Ative a imutabilidade no documento e confirme a letra i.

sudo chattr +i politica-rede.txt
lsattr politica-rede.txt

Entenda: O sinal + acrescenta o atributo; i significa imutável. Enquanto estiver ativo, novas tentativas de escrita, renomeação e remoção serão bloqueadas.

11. Fazer uma manutenção autorizada

O que fazer: Agora retire i, acrescente a mudança aprovada e leia o documento.

sudo chattr -i politica-rede.txt

Entenda: -i libera o arquivo para edição. O operador >> acrescenta uma linha ao final, preservando o conteúdo anterior.

O que observar: A nova linha deve aparecer. Isso mostra que um administrador autorizado pode retirar a proteção; i não impede alguém com esse privilégio de desativá-la.

12. Proteger a versão aprovada

O que fazer: Atualize o resumo do documento após conferir a mudança e ative i novamente.

sudo chattr +i politica-rede.txt

Entenda: O operador > substitui o resumo antigo no arquivo politica.sha256. Esta atualização é intencional: estamos aprovando uma nova versão do documento.

O que fazer: Troquem os papéis na dupla. Antes dos testes de conectividade, observem os endereços e as rotas da VM.

16. Registrar um teste local

O que fazer: Acrescente a data e faça três testes de ping para a própria VM. Aguarde o comando terminar.

date -Is >> conectividade.log
ping -c 3 -W 2 127.0.0.1 >> conectividade.log 2>&1
cat conectividade.log

Entenda: date -Is gera data e hora no formato ISO. ping -c 3 envia três solicitações; -W 2 define a espera por resposta em segundos. >> acrescenta a saída; 2>&1 inclui mensagens de erro no mesmo registro.

O que observar: O registro deve conter a data e o resultado do ping. 127.0.0.1 é loopback: testa a própria máquina, sem atravessar a LAN. Uma resposta local não comprova acesso a outros equipamentos.

whoami mostra o nome da conta que está usando o terminal. Nas próximas etapas, execute uma linha por vez. Não copie o símbolo $ de exemplos de terminal.

O QUE OBSERVAR
Deve aparecer aluno. Se aparecer root ou outro nome, entre na conta correta antes de continuar. Quando sudo pedir uma senha, digite a senha de aluno; nada aparece enquanto você digita. Se a conta não puder usar sudo, chame o professor.


02. Baixar a preparação

O QUE FAZER
Clique em Baixar preparação .sh. No gerenciador de arquivos do Debian, abra a pasta onde o navegador salvou preparar_atributos.sh. Nessa pasta, use Abrir no terminal.

DIGITE, UMA LINHA POR VEZ
ls preparar_atributos.sh

ENTENDA
ls verifica se o arquivo baixado está na pasta atual. Se o navegador estiver no computador físico, transfira primeiro o arquivo para a VM.

O QUE OBSERVAR
O nome preparar_atributos.sh deve aparecer. Se aparecer “Arquivo ou diretório inexistente”, você está na pasta errada: localize o download antes de continuar.


03. Criar os arquivos da atividade

O QUE FAZER
No terminal aberto na pasta do download, execute o roteiro abaixo uma única vez, sem sudo.

DIGITE, UMA LINHA POR VEZ
bash preparar_atributos.sh

ENTENDA
bash executa o roteiro. Ele cria uma pasta nova dentro da pasta pessoal de aluno, contendo uma política fictícia, um registro de conectividade e a pasta backup. Nenhuma regra real de rede é alterada.

O QUE OBSERVAR
Ao final, aparecerá uma linha começando com cd e um caminho como /home/aluno/lab-atributos.XXXXXX. O sufixo será diferente em cada execução.


04. Entrar na pasta criada

O QUE FAZER
Copie a linha inteira que começa com cd, exibida no passo anterior. Cole no mesmo terminal e pressione Enter. Depois execute:

DIGITE, UMA LINHA POR VEZ
pwd
ls

ENTENDA
cd entra na pasta criada. pwd mostra onde você está; ls lista os arquivos. Continue usando este mesmo terminal em toda a atividade.

O QUE OBSERVAR
O caminho deve terminar em lab-atributos seguido de um sufixo. Você deve ver politica-rede.txt, politica.sha256, conectividade.log, resolv.conf.lab e backup. Não digite XXXXXX literalmente.


05. Testar o suporte aos atributos

O QUE FAZER
Crie um arquivo de teste. Aplique i e consulte o resultado, nesta ordem.

DIGITE, UMA LINHA POR VEZ
touch teste-atributo
sudo chattr +i teste-atributo
lsattr teste-atributo

ENTENDA
touch cria um arquivo vazio. sudo autoriza a alteração administrativa; chattr +i ativa a imutabilidade. lsattr apenas consulta os atributos.

O QUE OBSERVAR
Procure a letra i antes do nome do arquivo. Outras letras, como e, podem aparecer. Se chattr não existir, der erro ou i não aparecer, pare e chame o professor. Não faça os testes de remoção sem confirmar a proteção.


06. Encerrar o teste de suporte

O QUE FAZER
Remova a proteção do arquivo de teste e confira. Registre também o sistema de arquivos utilizado.

DIGITE, UMA LINHA POR VEZ
sudo chattr -i teste-atributo
lsattr teste-atributo
findmnt -T .

ENTENDA
-i retira somente a imutabilidade. Em findmnt, -T consulta o sistema de arquivos que contém o caminho indicado; o ponto significa a pasta atual.

O QUE OBSERVAR
A letra i deve desaparecer. Anote o tipo indicado em FSTYPE, por exemplo ext4. Guarde essa saída para o relatório. Não é necessário apagar o arquivo de teste.


07. Ler a política de rede

O QUE FAZER
Vamos proteger um documento que descreve regras fictícias de rede. Leia seu conteúdo antes de alterar atributos.

DIGITE, UMA LINHA POR VEZ
cat politica-rede.txt

ENTENDA
cat mostra o texto. SSH usa TCP 22 para acesso administrativo; HTTPS usa TCP 443 para acesso web seguro. Este arquivo é apenas um documento: não configura o firewall.

O QUE OBSERVAR
Você verá as linhas criadas pelo roteiro. Registre o conteúdo inicial para comparar com os próximos testes.


08. Proteger a política com i

O QUE FAZER
Ative a imutabilidade no documento e confirme a letra i.

DIGITE, UMA LINHA POR VEZ
sudo chattr +i politica-rede.txt
lsattr politica-rede.txt

ENTENDA
O sinal + acrescenta o atributo; i significa imutável. Enquanto estiver ativo, novas tentativas de escrita, renomeação e remoção serão bloqueadas.

O QUE OBSERVAR
Só avance quando lsattr mostrar i. Se não mostrar, chame o professor e não execute o próximo passo.


09. Tentar alterar o documento

O QUE FAZER
Execute cada tentativa separadamente. Observe e registre a mensagem antes de passar à próxima linha.

DIGITE, UMA LINHA POR VEZ
echo "SSH aberto para qualquer origem" >> politica-rede.txt
mv politica-rede.txt politica-rede.old
sudo rm politica-rede.txt

ENTENDA
echo tenta acrescentar texto; mv tenta renomear; rm tenta remover. São testes apenas no arquivo didático cuja proteção foi confirmada no passo anterior.

O QUE OBSERVAR
As três operações devem falhar. A mensagem pode ser “Operação não permitida” ou “Permissão negada”. Aqui o erro é o resultado esperado; não tente contorná-lo.


10. Conferir se a política foi preservada

O QUE FAZER
Leia novamente o documento e confira sua impressão digital.

DIGITE, UMA LINHA POR VEZ
cat politica-rede.txt
sha256sum -c politica.sha256

ENTENDA
O roteiro salvou um resumo SHA-256 do conteúdo original. A opção -c compara o arquivo atual com esse resumo.

O QUE OBSERVAR
A conferência deve indicar OK e o texto original deve permanecer. Registre a saída. Se o arquivo sumiu ou a conferência falhou, pare e peça ajuda.


11. Fazer uma manutenção autorizada

O QUE FAZER
Agora retire i, acrescente a mudança aprovada e leia o documento.

DIGITE, UMA LINHA POR VEZ
sudo chattr -i politica-rede.txt
echo "Alteracao aprovada: monitoramento ICMP interno" >> politica-rede.txt
cat politica-rede.txt

ENTENDA
-i libera o arquivo para edição. O operador >> acrescenta uma linha ao final, preservando o conteúdo anterior.

O QUE OBSERVAR
A nova linha deve aparecer. Isso mostra que um administrador autorizado pode retirar a proteção; i não impede alguém com esse privilégio de desativá-la.


12. Proteger a versão aprovada

O QUE FAZER
Atualize o resumo do documento após conferir a mudança e ative i novamente.

DIGITE, UMA LINHA POR VEZ
sha256sum politica-rede.txt > politica.sha256
sudo chattr +i politica-rede.txt
lsattr politica-rede.txt

ENTENDA
O operador > substitui o resumo antigo no arquivo politica.sha256. Esta atualização é intencional: estamos aprovando uma nova versão do documento.

O QUE OBSERVAR
A política volta a mostrar i. No relatório, explique por que foi necessário retirar a proteção antes da manutenção.


13. Identificar a rede da VM

O QUE FAZER
Troquem os papéis na dupla. Antes dos testes de conectividade, observem os endereços e as rotas da VM.

DIGITE, UMA LINHA POR VEZ
ip -br address
ip route

ENTENDA
ip consulta a rede. -br abrevia a listagem; address mostra os endereços das interfaces. route mostra as rotas. lo é a interface de loopback; outras interfaces podem ter nomes como enp0s3.

O QUE OBSERVAR
Anote o IPv4 da interface de rede, se houver, e o gateway indicado na rota default, se existir. Peça ao professor o IP autorizado para o teste; não escolha um endereço ao acaso.


14. Salvar o estado da rede

O QUE FAZER
Salve as duas consultas em arquivos para anexar ao relatório.

DIGITE, UMA LINHA POR VEZ
ip -br address > ip-inicial.txt
ip route > rotas-iniciais.txt

ENTENDA
> envia a saída para um arquivo. Esses dois arquivos ainda não têm proteção; repetir os comandos substitui seus conteúdos.

O QUE OBSERVAR
Os comandos podem não mostrar nada no terminal, pois a saída foi gravada. Os arquivos ip-inicial.txt e rotas-iniciais.txt guardarão o estado da rede neste momento.


15. Proteger o histórico com a

O QUE FAZER
Leia o registro inicial, ative a proteção de acréscimo e consulte os atributos.

DIGITE, UMA LINHA POR VEZ
cat conectividade.log
sudo chattr +a conectividade.log
lsattr conectividade.log

ENTENDA
a permite acrescentar dados ao final, mas impede sobrescrever ou remover o arquivo. É diferente de i, que também impede acréscimos.

O QUE OBSERVAR
A letra a deve aparecer. Se ocorrer erro ou a não aparecer, pare e chame o professor. Só prossiga com os testes após essa confirmação.


16. Registrar um teste local

O QUE FAZER
Acrescente a data e faça três testes de ping para a própria VM. Aguarde o comando terminar.

DIGITE, UMA LINHA POR VEZ
date -Is >> conectividade.log
ping -c 3 -W 2 127.0.0.1 >> conectividade.log 2>&1
cat conectividade.log

ENTENDA
date -Is gera data e hora no formato ISO. ping -c 3 envia três solicitações; -W 2 define a espera por resposta em segundos. >> acrescenta a saída; 2>&1 inclui mensagens de erro no mesmo registro.

O QUE OBSERVAR
O registro deve conter a data e o resultado do ping. 127.0.0.1 é loopback: testa a própria máquina, sem atravessar a LAN. Uma resposta local não comprova acesso a outros equipamentos.


17. Informar o destino autorizado

O QUE FAZER
Digite o comando abaixo. Quando aparecer IP autorizado:, digite somente o IP indicado pelo professor e pressione Enter.

DIGITE, UMA LINHA POR VEZ
read -r -p "IP autorizado: " ALVO
echo "Destino: $ALVO" >> conectividade.log

ENTENDA
read lê o que você digitar. -r preserva barras invertidas; -p mostra a pergunta. ALVO guarda o IP; $ALVO recupera esse valor. Use o mesmo terminal no próximo passo.

O QUE OBSERVAR
A primeira linha fica aguardando sua entrada: isso é normal. Não cole o próximo comando enquanto ela espera o IP. Se não houver um destino disponível na aula, pule o teste externo e registre essa limitação.


18. Testar a comunicação pela rede

O QUE FAZER
Com o IP já informado, acrescente a data, faça o ping e leia o histórico.

DIGITE, UMA LINHA POR VEZ
date -Is >> conectividade.log
ping -c 3 -W 2 "$ALVO" >> conectividade.log 2>&1
cat conectividade.log

ENTENDA
As aspas em "$ALVO" mantêm o IP como um único argumento. O resultado é acrescentado ao mesmo arquivo, depois do teste local.

O QUE OBSERVAR
Anote o destino, os pacotes enviados/recebidos, a perda e o RTT quando houver respostas. Sem resposta não significa necessariamente equipamento desligado: ICMP pode estar filtrado ou pode haver isolamento da rede.


19. Tentar substituir e apagar o histórico

O QUE FAZER
Confirme novamente a letra a. Depois execute as duas tentativas, uma por vez. Ao final, leia o registro.

DIGITE, UMA LINHA POR VEZ
lsattr conectividade.log
echo "Registro substituido" > conectividade.log
rm conectividade.log
cat conectividade.log

ENTENDA
Agora usamos >, que tenta substituir o conteúdo, em vez de >>, que acrescenta. rm tenta remover o arquivo. Execute as tentativas somente se a estiver confirmado.

O QUE OBSERVAR
A substituição e a remoção devem falhar. Os testes de ping anteriores devem continuar no arquivo. Explique no relatório por que >> funcionou e > não funcionou.


20. Proteger somente a pasta

O QUE FAZER
Ative i na pasta backup e consulte os atributos da própria pasta.

DIGITE, UMA LINHA POR VEZ
sudo chattr +i backup
lsattr -d backup

ENTENDA
Em lsattr, -d mostra a pasta em si. Sem -R, chattr altera somente o objeto indicado; não aplica automaticamente a mesma proteção aos arquivos internos.

O QUE OBSERVAR
Confirme i na pasta backup antes do próximo passo. O arquivo backup/switch.cfg ainda não recebeu i.


21. Comparar pasta e arquivo interno

O QUE FAZER
Tente criar um arquivo novo e depois acrescentar uma linha a um arquivo que já existe dentro da pasta.

DIGITE, UMA LINHA POR VEZ
touch backup/novo.cfg
echo "Anotacao no arquivo existente" >> backup/switch.cfg
cat backup/switch.cfg

ENTENDA
A proteção da pasta impede criar novos nomes nela. O conteúdo de um arquivo interno é outro objeto e ainda não está imutável.

O QUE OBSERVAR
touch deve falhar, mas a anotação no arquivo existente deve aparecer. Essa diferença é a descoberta principal deste passo.


22. Proteger também o conteúdo

O QUE FAZER
Retire i da pasta e aplique novamente com -R. Depois consulte os arquivos internos.

DIGITE, UMA LINHA POR VEZ
sudo chattr -i backup
sudo chattr -R +i backup
lsattr -R backup

ENTENDA
-R significa recursivo: percorre a pasta e seu conteúdo. Assim, os arquivos existentes dentro dela também recebem i.

O QUE OBSERVAR
Procure i nos arquivos listados dentro de backup. Se a aplicação falhar ou os arquivos não mostrarem i, peça ajuda antes de continuar.


23. Repetir a edição do arquivo interno

O QUE FAZER
Tente acrescentar outra linha e depois confira o conteúdo.

DIGITE, UMA LINHA POR VEZ
echo "Outra anotacao" >> backup/switch.cfg
cat backup/switch.cfg

ENTENDA
Desta vez, o próprio switch.cfg tem i. A diferença foi aplicar chattr com -R no passo anterior.

O QUE OBSERVAR
A escrita deve falhar e “Outra anotacao” não deve aparecer no arquivo. Compare esse resultado com o passo em que somente a pasta estava protegida.


24. Retirar as proteções ao terminar

O QUE FAZER
Ainda na pasta do laboratório, libere os arquivos e a pasta usados nesta atividade.

DIGITE, UMA LINHA POR VEZ
sudo chattr -i politica-rede.txt
sudo chattr -a conectividade.log
sudo chattr -R -i backup

ENTENDA
-i retira imutabilidade; -a retira a restrição de acréscimo. Com -R, a retirada alcança também o conteúdo de backup.

O QUE OBSERVAR
Os comandos devem terminar sem erro. Não apague os arquivos: eles serão usados na entrega.


25. Conferir a liberação

O QUE FAZER
Consulte os arquivos, a pasta e seu conteúdo para confirmar a recuperação.

DIGITE, UMA LINHA POR VEZ
lsattr politica-rede.txt conectividade.log
lsattr -d backup
lsattr -R backup

ENTENDA
Estas consultas não alteram nada. Elas servem como evidência de que as proteções aplicadas durante a aula foram retiradas.

O QUE OBSERVAR
Não deve haver i nem a nesses objetos. Outras letras, como e, podem permanecer. Guarde a saída para anexar ao relatório.

Respondam: qual a diferença entre i e a? Por que proteger só a pasta não protege seu conteúdo? Por que root pode retirar a proteção? O que o ping local comprova? Identifiquem qualquer teste que não pôde ser realizado e expliquem o motivo.
