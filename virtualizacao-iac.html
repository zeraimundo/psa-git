Camadas de abstração

Três categorias principais de virtualização

A diferença está em onde a camada de virtualização é aplicada.

Nível de Hardware

Cria uma máquina virtual completa, com CPU, RAM, disco, rede e sistema operacional independente.

Ex.: KVM, ESXi, Hyper‑V, VirtualBox.

Nível de SO

Cria ambientes isolados que compartilham o kernel do sistema hospedeiro.

Ex.: containers Linux, LXC, Docker.

Nível de Aplicação

A aplicação roda sobre uma máquina virtual de software ou runtime.

Ex.: JVM, .NET CLR.
# Exemplo mental
Hardware → computador inteiro virtual
SO → ambientes isolados compartilhando kernel
Aplicação → runtime para executar programas
Ponto de atenção: VM e container não são sinônimos. A VM traz um SO convidado completo; o container compartilha o kernel do host.

Como a VM conversa com o processador?

Três formas de virtualização em x86

01

Virtualização total

O SO convidado não precisa ser modificado. O hardware é abstraído ou emulado, mas pode haver maior sobrecarga.

02

Para‑virtualização

O convidado fica “consciente” da virtualização e coopera com o hypervisor, reduzindo custos de emulação.

03

Assistida por hardware

Recursos do processador, como Intel VT‑x e AMD‑V, ajudam o hypervisor a gerenciar instruções de forma mais eficiente.

Analogia: virtualização total é como fingir que existe outro computador completo. Para‑virtualização é como dar ao convidado um “atalho” para falar melhor com o hypervisor.

Open Source

KVM e Xen: duas bases importantes da virtualização moderna

Ambos mostram como projetos abertos se tornaram fundamentais para data centers, nuvem e laboratórios.

KVM

Transforma o Linux em hypervisor, aproveitando os recursos do kernel e suporte de hardware.

Xen

Projeto clássico, com forte histórico em servidores, nuvem e para‑virtualização.

Otimização

Recursos avançados para reduzir gargalos

Quanto menos emulação desnecessária, mais próximo o desempenho fica de uma máquina física.

CPU Pinning

Vincula vCPUs/processos a núcleos físicos específicos. Ajuda a reduzir troca de contexto e perda de cache.

Memtune

Ajusta parâmetros de memória, cache e swap para melhorar estabilidade e desempenho.

VirtIO

Drivers paravirtualizados para disco e rede. A VM deixa de depender de emulação pesada de dispositivos antigos.

# Ideia prática
VM + drivers paravirtualizados → menos tradução → mais desempenho
VM + emulação genérica → mais compatibilidade, mas geralmente mais overhead

Ferramentas

Ansible e Terraform resolvem problemas diferentes

Configuração

Ansible

Excelente para automatizar configuração, instalação de pacotes, criação de usuários e execução de tarefas em servidores. Normalmente usa SSH e arquivos YAML chamados playbooks.

- name: instalar nginx
apt:
  name: nginx
  state: present
Provisionamento

Terraform

Excelente para criar infraestrutura base: VMs, redes, volumes, regras de firewall e recursos de nuvem, usando uma linguagem declarativa.

resource "vm" "lab" {
  cpu = 2
  memory = "4GB"
}
Resumo rápido: Terraform cria a infraestrutura; Ansible configura o que existe dentro dela. Em muitos ambientes, os dois trabalham juntos.
